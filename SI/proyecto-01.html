PR01 Walkthrough en acción

El proyecto PR01 representa la transición de la teoría a la práctica dentro del curso de Seguridad Informática. Su finalidad es demostrar que los conceptos estudiados en clase pueden aplicarse de forma controlada en un laboratorio, siguiendo una secuencia ordenada de análisis, explotación y documentación técnica.

A diferencia de una práctica puramente conceptual, este proyecto se enfoca en el desarrollo de un walkthrough completo sobre una máquina virtual vulnerable. El proceso incluye la preparación del entorno de pruebas, el reconocimiento exhaustivo del sistema, la enumeración de servicios, la identificación de vulnerabilidades, la explotación de debilidades presentes y la explicación clara de cada paso ejecutado.

🧪 Entorno: laboratorio controlado y aislado
🎯 Evidencia: explicación práctica del ataque

1) Objetivo general y objetivos específicos

Objetivo general

Demostrar la capacidad de aplicar conocimientos teóricos de seguridad informática en un entorno práctico, mediante la realización de un walkthrough detallado y la explicación de las técnicas y metodologías utilizadas para vulnerar una máquina virtual.

Objetivos específicos

  • Configurar un entorno de virtualización aislado para realizar las pruebas de penetración de forma segura.
  • Utilizar herramientas de escaneo de puertos y servicios para identificar posibles vectores de ataque.
  • Enumerar los servicios y aplicaciones en ejecución para obtener información detallada sobre el sistema objetivo.
  • Investigar las vulnerabilidades conocidas asociadas con los servicios y aplicaciones identificados.
  • Evaluar el riesgo y la viabilidad de explotar cada vulnerabilidad.
  • Seleccionar y adaptar los exploits adecuados para las vulnerabilidades encontradas.
  • Escalar privilegios para obtener acceso administrativo.
  • Registrar cada paso del proceso, incluyendo comandos utilizados, resultados obtenidos y capturas de pantalla.
  • Explicar las técnicas y metodologías utilizadas en cada etapa del ataque.
  • Grabar un video de la pantalla durante el proceso de ataque.
  • Explicar cada paso del proceso en detalle, utilizando un lenguaje claro y conciso.
  • Definir y explicar los términos técnicos utilizados durante el walkthrough.

Enfoque del proyecto

El valor principal de PR01 no está solo en “romper” una máquina vulnerable, sino en demostrar comprensión del proceso completo: preparación, análisis, decisión técnica, documentación y explicación. Por eso el walkthrough funciona tanto como evidencia práctica como recurso didáctico.

2) Introducción técnica del walkthrough

Un walkthrough de seguridad informática es una guía práctica y documentada que muestra de forma ordenada cómo se compromete un sistema vulnerable dentro de un entorno controlado. Su propósito académico no es fomentar ataques no autorizados, sino comprender cómo un atacante identifica debilidades, cómo se encadenan distintas técnicas y cómo puede evaluarse la exposición real de un sistema ante errores de configuración o software vulnerable.

En este proyecto, el walkthrough parte de la preparación de una máquina virtual vulnerable y continúa con una fase de reconocimiento y enumeración. Posteriormente se analizan las vulnerabilidades detectadas para decidir cuáles son explotables y bajo qué condiciones. Una vez obtenido el acceso inicial, se realizan actividades de post-explotación para demostrar control del sistema, escalamiento de privilegios y comprensión del impacto técnico.

Todo el proceso se documenta de manera estructurada mediante comandos, resultados, capturas y una grabación en video. De esta manera, PR01 se convierte en una evidencia completa del uso responsable de metodologías ofensivas con fines educativos.

3) Metodología general del proceso

Fases del walkthrough

  • Preparación del entorno de pruebas.
  • Reconocimiento del sistema objetivo.
  • Escaneo y enumeración de servicios.
  • Análisis de vulnerabilidades presentes.
  • Selección de técnicas y exploits adecuados.
  • Explotación del sistema vulnerable.
  • Post-explotación y escalamiento de privilegios.
  • Documentación final y grabación del video.

Criterios de desarrollo

  • Uso de un laboratorio controlado.
  • Aplicación ordenada de cada fase.
  • Justificación técnica de decisiones.
  • Lenguaje claro en la explicación.
  • Énfasis en el aprendizaje y la documentación.
Nota del proyecto: este walkthrough se presenta con fines académicos y de práctica controlada. El enfoque se mantiene dentro de un laboratorio aislado y documentado.

4) Desarrollo del proceso de ataque

Preparación del entorno

La primera etapa del proyecto consiste en preparar un entorno seguro para ejecutar las pruebas. Esto implica seleccionar una máquina virtual vulnerable adecuada, configurarla dentro de un sistema de virtualización aislado y verificar la conectividad necesaria entre la máquina atacante y la máquina objetivo. Esta fase es indispensable porque garantiza que el ejercicio no afecte sistemas reales y que todas las pruebas se desarrollen bajo condiciones controladas.

Reconocimiento y enumeración

Una vez listo el entorno, se realiza el reconocimiento del sistema objetivo con el fin de identificar puertos abiertos, servicios en ejecución, versiones de software y posibles puntos de entrada. La enumeración permite reunir información detallada sobre el estado del sistema y constituye la base para decidir qué vectores de ataque merecen investigarse con mayor profundidad.

Análisis de vulnerabilidades

Después de identificar los servicios expuestos, se investigan vulnerabilidades conocidas asociadas a dichos componentes. En esta etapa no basta con listar fallos potenciales: es necesario valorar si una vulnerabilidad es realmente explotable en ese contexto, qué nivel de acceso puede otorgar y qué condiciones se requieren para comprometer el sistema.

Explotación

La fase de explotación consiste en seleccionar y adaptar el método más adecuado para obtener acceso inicial al sistema. Esta etapa demuestra la aplicación práctica de los conceptos analizados previamente, ya que exige interpretar la información recolectada, elegir una técnica compatible con el entorno y ejecutar el procedimiento con precisión.

Post-explotación y escalamiento de privilegios

Una vez obtenido el acceso, el walkthrough continúa con actividades de post-explotación orientadas a demostrar el nivel de control alcanzado sobre la máquina. Esto puede incluir revisión de archivos, validación de privilegios y búsqueda de mecanismos para escalar a un nivel administrativo. Esta fase es clave porque muestra cómo un acceso inicial limitado puede convertirse en control total si el sistema presenta configuraciones débiles adicionales.

7) Conclusiones

PR01 demuestra que la seguridad informática no puede entenderse únicamente desde la teoría. La realización de un walkthrough permite visualizar de manera concreta cómo un atacante analiza un sistema, identifica debilidades y aprovecha errores de configuración o servicios vulnerables para comprometer una máquina.

También evidencia la importancia de la documentación técnica. Registrar comandos, resultados y decisiones convierte el ejercicio en un recurso formativo mucho más sólido, ya que no solo muestra el éxito del proceso, sino también el razonamiento detrás de cada etapa.

En conjunto, este proyecto fortalece la comprensión práctica de metodologías de pentesting, mejora la capacidad de análisis técnico y consolida la relación entre conceptos teóricos y aplicación real en laboratorio.
