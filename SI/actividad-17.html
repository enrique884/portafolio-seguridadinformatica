Actividad 17: Evaluación de Vulnerabilidades con CVSS v3.1

Análisis técnico de una vulnerabilidad en un sistema web interno mediante métricas base, vector CVSS, cálculo de puntuación y clasificación de severidad.

1. Introducción

La seguridad de la información se ha convertido en un elemento fundamental para las organizaciones modernas debido al incremento constante de amenazas y vulnerabilidades presentes en los sistemas tecnológicos. En entornos corporativos, una vulnerabilidad puede comprometer la confidencialidad, integridad y disponibilidad de la información, generando riesgos operativos, financieros y reputacionales.

El sistema Common Vulnerability Scoring System (CVSS) versión 3.1 es uno de los estándares más utilizados para evaluar la severidad de vulnerabilidades de seguridad informática. Este modelo proporciona un mecanismo estructurado para medir la gravedad de una vulnerabilidad mediante métricas técnicas relacionadas con la facilidad de explotación, el nivel de privilegios requerido y el impacto potencial sobre los activos de información.

En esta actividad se analiza una vulnerabilidad detectada en un sistema web interno. A partir del escenario, se identifican las métricas base correspondientes, se construye el vector CVSS y se interpreta la puntuación de riesgo obtenida.

2. Objetivos

General

Aplicar CVSS v3.1

Evaluar la gravedad de una vulnerabilidad e interpretar correctamente sus métricas base para justificar la priorización del riesgo en un contexto organizacional.

Específico

Identificar métricas

Reconocer las métricas base de CVSS v3.1 y comprender cómo influyen en la puntuación final.

Específico

Construir vector

Traducir el escenario técnico a un vector CVSS válido y explicar cada valor asignado.

3. Marco teórico

3.1 ¿Qué es una vulnerabilidad?

Una vulnerabilidad es una debilidad o falla presente en un sistema, aplicación, red o dispositivo que puede ser aprovechada por un atacante para comprometer la seguridad de la información. Estas vulnerabilidades pueden originarse por errores de configuración, fallas de programación, software desactualizado o malas prácticas de seguridad.

Confidencialidad

Garantiza que la información solo sea accesible para usuarios autorizados. Una vulnerabilidad puede provocar filtración o robo de datos sensibles.

Integridad

Asegura que la información no sea modificada de manera no autorizada. Una vulnerabilidad puede permitir alteraciones indebidas en archivos o bases de datos.

Disponibilidad

Garantiza que los sistemas y servicios estén disponibles cuando se necesiten. Una vulnerabilidad puede ocasionar interrupciones o caídas del sistema.

3.2 ¿Qué es CVSS v3.1?

CVSS v3.1 es un estándar internacional desarrollado por FIRST para evaluar la severidad de vulnerabilidades de seguridad informática. Su objetivo principal es proporcionar un método estandarizado que permita medir el nivel de riesgo mediante una puntuación numérica de 0.0 a 10.0.

3.3 Estructura de CVSS

Métricas base

Representan las características fundamentales de la vulnerabilidad. Son las más importantes porque determinan la puntuación principal de severidad.

Métricas temporales

Consideran factores que pueden cambiar con el tiempo, como exploits públicos, herramientas disponibles o actualizaciones liberadas por el fabricante.

Métricas ambientales

Permiten ajustar la evaluación al contexto de la organización, considerando la importancia de los activos afectados y requisitos internos.

3.4 Métricas base CVSS v3.1

Métrica Nombre Significado
AV Attack Vector Define desde dónde puede explotarse la vulnerabilidad: red, adyacente, local o físico.
AC Attack Complexity Indica el nivel de complejidad necesario para ejecutar el ataque exitosamente.
PR Privileges Required Representa el nivel de privilegios que necesita el atacante antes de explotar la vulnerabilidad.
UI User Interaction Determina si se requiere interacción de un usuario legítimo para que el ataque funcione.
S Scope Indica si la vulnerabilidad afecta únicamente al sistema vulnerable o puede impactar otros componentes.
C Confidentiality Mide el impacto sobre la confidencialidad de la información.
I Integrity Evalúa el impacto sobre la integridad de los datos o sistemas.
A Availability Mide el impacto sobre la disponibilidad de los servicios o recursos afectados.

3.5 Clasificación de severidad

Rango de puntuación Nivel de severidad Descripción
0.1 - 3.9 Baja Impacto limitado y riesgo reducido para la organización.
4.0 - 6.9 Media Puede afectar parcialmente la seguridad de los activos de información y requiere atención.
7.0 - 8.9 Alta Representa un riesgo considerable y puede generar impactos importantes.
9.0 - 10.0 Crítica Impacto extremadamente grave. Requiere atención inmediata.

4. Caso práctico

4.1 Escenario

Una organización detectó una vulnerabilidad dentro de un sistema web interno utilizado para la gestión de información corporativa. El análisis preliminar determinó que puede ser explotada remotamente a través de la red, sin necesidad de acceso físico al sistema comprometido.

La explotación presenta una baja complejidad técnica, por lo que no requiere condiciones especiales o avanzadas. Sin embargo, el atacante necesita contar con privilegios elevados dentro del sistema. Además, no requiere interacción por parte del usuario y no provoca cambios en el alcance de seguridad del sistema afectado.

Respecto al impacto potencial, se determinó que las afectaciones sobre la confidencialidad, integridad y disponibilidad son de nivel bajo, debido a que la vulnerabilidad compromete parcialmente los recursos del entorno evaluado sin generar una afectación crítica sobre la operación general.

4.2 Identificación de métricas

Característica del escenario Métrica CVSS Valor Justificación
Explotable por red AV N El ataque puede ejecutarse remotamente mediante conexión de red.
Baja complejidad AC L No requiere condiciones especiales ni pasos técnicos avanzados.
Privilegios elevados PR H El atacante debe contar con privilegios altos antes de explotar la vulnerabilidad.
Sin interacción UI N El ataque no depende de que un usuario legítimo realice alguna acción.
Alcance sin cambios S U El impacto permanece dentro del mismo componente o sistema vulnerable.
Impacto bajo en confidencialidad C L Solo puede existir exposición parcial de información.
Impacto bajo en integridad I L Podrían realizarse modificaciones limitadas, sin comprometer totalmente el sistema.
Impacto bajo en disponibilidad A L La afectación al servicio sería menor o parcial.

4.3 Construcción del vector CVSS

Con base en las métricas identificadas, se construye el siguiente vector CVSS v3.1: 

CVSS:3.1/AV:N/AC:L/PR:H/UI:N/S:U/C:L/I:L/A:L
01 Escenario

Se analiza cómo se explota la vulnerabilidad y qué condiciones requiere.

02 Métricas

Se asignan valores a AV, AC, PR, UI, S, C, I y A.

03 Vector

Se construye el vector CVSS v3.1 con los valores seleccionados.

04 Puntuación

Se obtiene el puntaje base y se interpreta la severidad.

5. Interpretación

A pesar de requerir privilegios elevados, esta vulnerabilidad sigue siendo relevante porque representa un riesgo que podría ser explotado por un atacante interno malintencionado o por un agente externo que ya haya comprometido una cuenta administrativa mediante otros métodos.

El tipo de atacante que podría explotarla es un insider, como un empleado o colaborador con acceso, o un atacante avanzado que busque ampliar su control después de una intrusión inicial. Que el impacto sea bajo en confidencialidad, integridad y disponibilidad significa que la explotación exitosa solo permitiría un acceso parcial a información, modificaciones limitadas o interrupciones menores.

6. Cálculo de puntuación

4.7 MEDIA

Puntuación base obtenida

La puntuación base calculada para el vector CVSS:3.1/AV:N/AC:L/PR:H/UI:N/S:U/C:L/I:L/A:L es de 4.7, lo que corresponde a una severidad Media.

Aunque el impacto en la triada CIA es bajo, la vulnerabilidad debe atenderse porque puede ser explotada por red, no requiere interacción del usuario y tiene baja complejidad técnica.

6.2 Priorización del riesgo

A Riesgo técnico

Medio, porque requiere privilegios altos pero puede ejecutarse por red.

B Impacto operativo

Limitado, ya que la afectación a datos y servicios es baja.

C Probable atacante

Usuario interno con privilegios o atacante externo con cuenta comprometida.

D Atención recomendada

Mitigación planificada, revisión de privilegios y monitoreo de cuentas administrativas.

7. Recomendaciones de mitigación

Mínimo privilegio

Revisar permisos administrativos y limitar el acceso solo a usuarios que realmente lo necesiten.

Monitoreo de cuentas

Detectar accesos anómalos, intentos de abuso de privilegios y comportamientos fuera de patrón.

Corrección del sistema web

Validar controles de autorización, endurecer configuraciones y aplicar parches o cambios de seguridad.

Reevaluación CVSS

Recalcular la puntuación después de aplicar medidas correctivas para confirmar la reducción del riesgo.

8. Conclusión

El análisis realizado mediante CVSS v3.1 permitió identificar y evaluar la severidad de una vulnerabilidad presente en un sistema web interno, determinando una puntuación base de 4.7, correspondiente a un nivel de severidad media.

Aunque la vulnerabilidad requiere privilegios elevados para ser explotada y su impacto en confidencialidad, integridad y disponibilidad es bajo, sigue representando un riesgo que debe atenderse. La posibilidad de explotación remota, la baja complejidad del ataque y la ausencia de interacción del usuario justifican una mitigación planificada.

Esta actividad demuestra que CVSS ayuda a convertir características técnicas en una evaluación cuantitativa, facilitando la priorización de vulnerabilidades y la toma de decisiones dentro de la seguridad organizacional.
